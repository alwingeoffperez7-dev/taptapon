# Surface: TapTapon web UI (student, admin, simulator)

Scope: dashboard/index.html (student, phone), dashboard/admin.html (staff, laptop), simulator/index.html (dev tool). Mode: Operate.
Audience/job: student checks points at the bin, one-handed, outdoors; staff scan bin state and approve claims. Demoed at the defense, then piloted.

## Direction contract
THESIS: The bin's own civic language. Points and bins read like the stenciled labels on barangay MRF drums; refuses the generic white-card + one-accent dashboard.
OWN-WORLD: Deep civic green shell (#0F4A33 field, #0B2E21 ink) on a pale green concrete ground (#EEF3EC). Lime #C4EA5A only for points earned. Signage amber/red only for bin state. Stencil numerals (Big Shoulders Stencil Display) for numbers and tags only; Atkinson Hyperlegible for all UI text. Square-ish 6px corners, painted 2px rules.
STORY: Student sees their number big and green, then why each deposit did or didn't count, then what it buys. Staff see which drum needs a janitor first.
FIRST VIEWPORT: Student: green painted panel with name, monumental stencil points, today's cap meter; lookup lives in the header. Admin: green header, row of stat plates, then drum gauges in a fixed-scale row.
SIGNATURE MOVE: Drum gauge: bin fill drawn as a painted drum with level ticks at 50/80; FULL adds hazard stripes, OFFLINE goes dashed. Same scale everywhere.
RAISES: from emission-line rail: state carried by line form, not hue alone. From botanical folio: every gauge at identical scale and baseline. From airport wayfinding: one monumental number per panel. From warm consumer app: action green only on pressable things.
FORM: assigned candidate 5 of 7 (barangay segregation signage); seed key 9a73b8b1.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
